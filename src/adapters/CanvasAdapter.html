Adapter

CanvasAdapter

Traduce un gioco Canvas 2D in pacchetti per il Core. Legge una lista di rettangoli, calcola le collisioni, misura gli FPS del gioco e disegna gli hitbox su un canvas sovrapposto: i pixel del gioco non si toccano.

Il gioco non parla mai con l'overlay. Aggiorna le entità e chiama pump().

Uso base

Serve un BeeLadybugCore, il canvas del gioco e la lista delle entità. Dopo attach(), chiama pump() una volta per frame, a posizioni già aggiornate.

game.js
import { BeeLadybugCore, CanvasAdapter } from 'bee-ladybug';

const canvas = document.getElementById('game');
const player = { name: 'player', x: 40, y: 40, width: 32, height: 32 };
const wall   = { name: 'wall',   x: 120, y: 30, width: 60, height: 80 };

const bee = new BeeLadybugCore();
const adapter = new CanvasAdapter(bee, { canvas, entities: [player, wall] });
adapter.attach();

function loop() {
  requestAnimationFrame(loop);
  update();        // muovi le entità
  draw();          // disegna il gioco
  adapter.pump();  // una volta per frame, alla fine
}
requestAnimationFrame(loop);

L'adapter tiene la lista per riferimento: se modifichi gli oggetti, li rilegge a ogni pump(). Per sostituire l'intera lista usa setEntities(). Senza bundler, nell'import usa il percorso ./node_modules/bee-ladybug/src/index.js, come in Inizia.

Le entità

Ogni entità è un rettangolo allineato agli assi (AABB), in pixel del canvas, cioè in unità degli attributi width e height e non della grandezza CSS. I campi in più vengono ignorati.

Campo Significato
x / worldX Posizione orizzontale. Se ci sono tutti e due, vince worldX.
y / worldY Posizione verticale. Se ci sono tutti e due, vince worldY.
width / w Larghezza. Se ci sono tutti e due, vince width.
height / h Altezza. Se ci sono tutti e due, vince height.
name Nome mostrato sull'hitbox e nei messaggi. Se manca: label, poi id, poi #indice.
id Opzionale. Serve a riconoscere la stessa entità da un frame all'altro.
active Con false l'hitbox è grigio. Non cambia le collisioni.
colliding Con true l'entità conta come in collisione, anche senza sovrapposizioni.
primary Con true è l'entità seguita dal pacchetto coord.

I valori devono essere numeri finiti: una stringa come '40' non vale. Un'entità senza posizione valida, o con larghezza o altezza pari a 0 o negative, viene scartata in silenzio e non compare in entities.

Il pacchetto coord segue la prima entità con primary: true oppure con nome player o hero (maiuscole ininfluenti). Se non c'è, segue la prima entità valida.

Opzioni

Opzione Default Effetto
canvas null Il canvas del gioco. Senza, la telemetria funziona ma gli hitbox non si disegnano.
entities [] La lista delle entità.
overlay true Disegna gli hitbox su un canvas sovrapposto.
computeCollisions true Calcola le sovrapposizioni. Con false conta solo colliding: true.
autoPump false Chiama pump() da un ciclo interno. Vedi autoPump.
colorActive '#3dff6a' Colore degli hitbox normali.
colorColliding '#ff3b3b' Colore degli hitbox in collisione.
colorInactive '#8a8a8a' Colore delle entità con active: false.
source 'canvas' Il source di tutti i pacchetti. Per il Core è anche il nome del modulo.

Cosa invia al Core

Tutti i pacchetti portano source: 'canvas'. Il formato di ogni tipo è nel contratto sendData.

Tipo Quando Contenuto
fps A ogni pump(), dalla seconda chiamata value: FPS del gioco, misurati tra un pump() e l'altro
metric A ogni pump() entities: entità valide. hits: entità in collisione.
state A ogni pump() key: 'hits', value come '2 / 5'
coord A ogni pump(), se c'è un'entità valida label: nome dell'entità seguita, x, y
warn Un'entità entra in collisione message: player entered collision
log Un'entità esce dalla collisione message: player left collision
log, state attach() CanvasAdapter attached (N entities). e key: 'adapter'
warn attach() con overlay attivo e senza canvas no canvas: hitboxes are not drawn…, una volta sola
warn pump() a mano mentre autoPump è attivo pump() skipped…, una volta sola

Il messaggio di collisione usa sempre il nome dell'entità, anche quando ha un id. Nell'overlay del Core finiscono in console solo log e warn: fps, metric, state e coord vanno nell'HUD e nello storico.

Overlay degli hitbox

Con overlay: true l'adapter crea un canvas fisso sopra al tuo, con pointer-events: none, e lo tiene allineato a quello del gioco quando la pagina viene ridimensionata o scorre. Ogni rettangolo ha il suo nome sopra l'angolo.

Colore Significato
Verde (colorActive) Entità attiva, senza collisione
Rosso (colorColliding) Entità in collisione, con riempimento rosso leggero
Grigio (colorInactive) Entità con active: false

F2 nasconde il pannello e anche gli hitbox. Il pulsante CANVAS nel pannello fa di più: spegne l'adapter. Gli hitbox spariscono, pump() non invia più niente e il report (snapshot()) resta disponibile.

Il canvas del gioco può arrivare dopo: setCanvas(canvas) monta l'overlay, setCanvas(null) lo toglie.

Disegnare sul canvas del gioco

Con overlay: false non nasce nessun canvas in più. Passa il contesto 2D a pump(ctx) e gli hitbox vengono disegnati sul canvas del gioco. In questo caso l'adapter non lo pulisce: chiama pump(ctx) dopo aver disegnato il frame.

js
const ctx = canvas.getContext('2d');
const adapter = new CanvasAdapter(bee, { canvas, entities, overlay: false });
adapter.attach();

// nel loop, dopo aver disegnato il gioco:
adapter.pump(ctx);

Freeze e slow

Con F4 e F3 (o bee.freeze() e bee.setTimeScale()) il Core cambia il suo clock. L'adapter non ferma il gioco: copia i valori in adapter.frozen e adapter.timeScale, e sta al tuo codice rispettarli.

js
function update(dt) {
  if (adapter.frozen) return;
  const step = dt * adapter.timeScale;
  player.x += speed * step;
}

Il conteggio degli FPS non si ferma con il freeze: misura sempre il tempo tra due pump().

autoPump

Dalla console o da un bookmarklet non puoi entrare nel ciclo del gioco. Con autoPump: true l'adapter chiama pump() da solo, a ogni requestAnimationFrame.

js
const adapter = new CanvasAdapter(bee, { canvas, entities, autoPump: true });
adapter.attach();

// più tardi: da qui in poi puoi chiamare pump() a mano
adapter.stopAutoPump();

Mentre il ciclo interno è attivo, un pump() chiamato a mano viene saltato, con un solo avviso (anche in console del browser). startAutoPump() lo riaccende, stopAutoPump() lo ferma e rende di nuovo valido pump() a mano. detach() ferma il ciclo, ma non cambia autoPump: un nuovo attach() lo riavvia.

Metodi

Tutti i metodi, tranne snapshot(), restituiscono l'adapter e si possono concatenare.

Metodo Cosa fa
attach() Si registra nel Core come canvas (etichetta CANVAS, nessun tasto), monta l'overlay e avvia autoPump se è attivo.
detach() Si toglie dal Core, smonta l'overlay, ferma il ciclo interno e azzera collisioni, campioni FPS e tempi. Un attach() successivo riparte pulito.
pump(ctx?) Un frame di telemetria. Il contesto serve solo con overlay: false.
setCanvas(canvas | null) Cambia il canvas del gioco. Con null smonta l'overlay.
setEntities(list) Sostituisce la lista delle entità.
startAutoPump() Accende il ciclo interno.
stopAutoPump() Spegne il ciclo interno e imposta autoPump a false.
snapshot() Le righe per il report. Vale null se l'adapter non è attaccato.

Le proprietà che ti servono sono frozen, timeScale, canvas e entities.

Nel report (F8)

Il report HTML (F8 o bee.exportReport()) include una sezione canvas con questo contenuto di snapshot():

Riga Contenuto
hitbox, una per entità Nome, posizione e dimensione, per esempio 40,40 32x32, con colliding in fondo se è in collisione. Gravità warn se in collisione, altrimenti ok. Numeri arrotondati a un decimale.
fps min, avg e max degli FPS del gioco. Compare dopo almeno due pump().

Limiti

Le collisioni sono tra rettangoli senza rotazione, e ogni entità viene confrontata con tutte le altre: il costo cresce col quadrato del numero di entità. A ogni frame partono circa cinque pacchetti, più quelli di collisione. Se hai molte entità, spegni computeCollisions e segna tu colliding.

▶ Prova in console

Apri una pagina qualsiasi, premi F12 e incolla (se Chrome blocca l'incolla, scrivi allow pasting e riprova). Lo snippet carica bee-ladybug@0.6.4 dalla CDN, crea in alto a sinistra un canvas di prova con due rettangoli, player e wall, e usa autoPump perché dalla console non hai il ciclo del gioco.

console
import('https://cdn.jsdelivr.net/npm/bee-ladybug@0.6.4/src/index.js')
  .then(({ BeeLadybugCore, CanvasAdapter }) => {
    const canvas = document.createElement('canvas');
    canvas.width = 320;
    canvas.height = 180;
    canvas.style.cssText = 'position:fixed;left:16px;top:16px;background:#1e1e24;z-index:2147483000';
    document.body.appendChild(canvas);

    const player = { name: 'player', x: 20, y: 60, width: 40, height: 40 };
    const wall = { name: 'wall', x: 140, y: 40, width: 60, height: 90 };

    const bee = new BeeLadybugCore();
    const adapter = new CanvasAdapter(bee, { canvas, entities: [player, wall], autoPump: true });
    adapter.attach();
    Object.assign(window, { bee, adapter, player, wall });
  });

Poi muovi il giocatore contro il muro e fallo uscire di nuovo:

console
player.x = 150
player.x = 20

Con player.x = 150 i due hitbox diventano rossi e nella console del pannello compaiono player entered collision e wall entered collision; con 20 escono player left collision e wall left collision. F2 nasconde pannello e hitbox, F8 scarica il report con la sezione canvas.
