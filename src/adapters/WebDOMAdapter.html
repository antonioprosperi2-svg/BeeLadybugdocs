Adapter

WebDOMAdapter

Traduce il DOM di una pagina HTML in pacchetti per il Core. Segue l'elemento sotto il puntatore, ne disegna il box model (margin, border, padding, content) su un canvas sovrapposto, tiene d'occhio i selettori in watch e conta le mutazioni del DOM.

La pagina non sa che la stai ispezionando. L'overlay è in pointer-events: none.

Uso base

Passa il BeeLadybugCore e, se vuoi limitare l'ispezione a una porzione di pagina, l'elemento root (di default è document.body) e i selettori CSS in watch.

app.js
import { BeeLadybugCore, WebDOMAdapter } from 'bee-ladybug';

const bee = new BeeLadybugCore();
const dom = new WebDOMAdapter(bee, {
  root: document.body,
  watch: ['.card', '#cta']
});
dom.attach();

Con autoTick: true (il default) l'adapter avvia da solo il suo ciclo requestAnimationFrame: non devi chiamare pump() a mano. Senza bundler, nell'import usa il percorso ./node_modules/bee-ladybug/src/index.js, come in Inizia.

Opzioni

I valori predefiniti sono esportati anche in WEB_DOM_ADAPTER_DEFAULTS.

Opzione Default Effetto
root document.body Radice osservata per hover, conteggio nodi, selettori watch, mutazioni e problemi nel report. Se passi null, puoi impostarla dopo con setRoot().
overlay true Monta un canvas fisso a tutta finestra che disegna il box model e i contorni watch.
autoTick true Chiama pump() a ogni requestAnimationFrame. Con false chiami tu pump() quando vuoi.
watch [] Lista di selettori CSS cercati dentro root. I nodi trovati vengono contornati in verde sull'overlay e inclusi nel report. Selettori non validi vengono ignorati senza errori.
source 'dom' Il source di tutti i pacchetti inviati al Core.
colorHover '#6ee7ff' Colore del bordo e dell'etichetta dell'elemento sotto il puntatore.
colorWatch '#3dff6a' Colore del contorno per gli elementi in watch.
colorMargin 'rgba(255, 211, 106, 0.18)' Riempimento dell'area di margin.
colorPadding 'rgba(61, 255, 106, 0.16)' Riempimento dell'area di padding.
colorContent 'rgba(110, 231, 255, 0.20)' Riempimento dell'area di content.

Hover, selettori watch e overlay

Quando muovi il mouse, l'adapter usa document.elementsFromPoint(x, y) per trovare il primo elemento sotto il puntatore che sta dentro root, ignorando sempre l'overlay di BeeLadybug e i canvas di servizio ([data-bee-ladybug-dom] e [data-bee-ladybug-canvas]).

Ogni elemento viene identificato con un selettore compatto: tag#id se ha un id, altrimenti tag.classe1.classe2 (fino alle prime due classi), altrimenti solo tag.

Area sull'overlay Cosa mostra
Margin (ambra) Fascia esterna calcolata da marginTop/Right/Bottom/Left
Border (ciano) Rettangolo di getBoundingClientRect() contornato con colorHover
Padding (verde) Fascia interna tra bordo e contenuto
Content (azzurro) Area utile interna del nodo
Etichetta Selettore e dimensioni arrotondate (es. div.card 320×180), riposizionata dentro la finestra se tocca i bordi
Nodi watch Contorno verde (colorWatch) su tutti i nodi che corrispondono ai selettori in watch

F2 nasconde il pannello del Core e anche il canvas del box model. Il pulsante DOM nel pannello spegne l'adapter: l'overlay sparisce, pump() e il conteggio delle mutazioni si fermano, mentre snapshot() resta disponibile per il report.

Mutazioni del DOM e filtro rumore

Se root è presente, attach() attiva un MutationObserver su childList, subtree e sugli attributi class, style, hidden, disabled e open. Le modifiche ai nodi interni di BeeLadybug vengono scartate.

Le mutazioni vengono raggruppate in una finestra di 180 ms così una raffica di modifiche non intasa la console: allo scadere parte un pacchetto metric (name: 'mutations') con il totale e un warn sintetico come mutate +2 -1 attr 3.

Silenzio automatico durante la CSS hunt (F6)

Quando CSSAdapter (F6) è attivo a velocità normale (1x) o in freeze (F4), le righe di hover in console e la parte attr N dei warn di mutazione vengono silenziate per lasciare spazio ai messaggi CSS. Se invece attivi lo slow-motion (F3), anche hover e attributi tornano visibili. La funzione che decide questa regola è esportata come domNoiseQuiet(cssEnabled, frozen, timeScale).

Cosa invia al Core

Tutti i pacchetti portano source: 'dom'. Il formato generale è nel contratto sendData.

Tipo Quando Contenuto
fps A ogni pump(), dalla seconda chiamata value: frequenza di campionamento dell'adapter
metric A ogni pump() name: 'nodes', numero di elementi dentro root (incluso root se è un elemento)
coord A ogni pump() label: 'pointer', coordinate x e y del puntatore
state Con un nodo in hover Tre stati HUD: hover (selettore), box (es. 320×180) e display (es. flex). Quando l'hover torna a null, tutti e tre tornano a '—'.
log Quando cambia il nodo sotto il puntatore hover div.card 320×180 block (silenziato se la CSS hunt è attiva senza F3)
warn Dopo 180 ms dalle mutazioni DOM mutate +added -removed attr N
metric Dopo 180 ms dalle mutazioni DOM name: 'mutations', somma di nodi aggiunti, rimossi e attributi toccati
log, state attach() WebDOMAdapter attached… e key: 'adapter', value: 'dom'

Freeze (F4) e slow (F3)

Quando premi F4 (o chiami bee.freeze()), l'adapter imposta dom.frozen = true: blocca l'elemento in hover sull'ultimo nodo selezionato (così puoi spostare il mouse senza perdere il box model) e ignora le nuove mutazioni del DOM finché non togli il freeze.

Metodi

Tutti i metodi, tranne snapshot(), restituiscono l'adapter e si possono concatenare.

Metodo Cosa fa
attach() Si registra nel Core come dom (etichetta DOM, nessun tasto), monta l'overlay, avvia il MutationObserver e il ciclo autoTick.
detach() Si rimuove dal Core, disconnette l'observer, smonta l'overlay e azzera hover, FPS e contatori di mutazione. Un attach() successivo riparte pulito.
setRoot(root | null) Cambia il nodo radice osservato. Disconnette il vecchio observer, ne avvia uno nuovo (anche se l'adapter era partito con root: null) e azzera hover se non cade dentro il nuovo root. Con null ferma l'osservazione.
pump() Esegue un campionamento e ridisegna l'overlay. Utile se hai impostato autoTick: false.
snapshot() Restituisce le righe per il report (F8). Vale null quando l'adapter è staccato.

Le proprietà pubbliche principali sono root, watch, hover, frozen e timeScale.

Nel report (F8)

Il report (F8 o bee.exportReport()) include una sezione dom generata da snapshot(). Gli elementi nascosti (display: none, visibility: hidden), la barra admin di WordPress (#wpadminbar) e l'interfaccia di BeeLadybug vengono esclusi automaticamente.

Regola (rule) Gravità Contenuto
box ok Box model completo del nodo in hover e dei nodi in watch: border WxH margin T,R,B,L padding T,R,B,L content WxH display.
negative margin warn Nodi dentro root con almeno un margine negativo (es. 0,0,0,-12).
clipped warn Nodi il cui contenuto eccede il box di oltre 2 px: scroll SWxSH client CWxCH.
collapsed content warn Nodi con bordo visibile (w > 0 e h > 0) ma area content schiacciata a 0 su larghezza o altezza.
mutations warn se > 0, altrimenti ok Conteggio dell'ultima raffica (o di quella in attesa di flush): +added -removed attr N.

Per non appesantire il report su pagine molto grandi, le righe di problemi (negative margin, clipped, collapsed content) sono limitate a un massimo di 40.

▶ Prova in console

Apri una pagina qualsiasi, premi F12 e incolla (se Chrome blocca l'incolla, scrivi allow pasting e riprova). Lo snippet carica bee-ladybug@0.6.4 dalla CDN e attiva WebDOMAdapter sul body mettendo in watch i titoli e i pulsanti.

console
import('https://cdn.jsdelivr.net/npm/bee-ladybug@0.6.4/src/index.js')
  .then(({ BeeLadybugCore, WebDOMAdapter }) => {
    const bee = new BeeLadybugCore();
    const dom = new WebDOMAdapter(bee, {
      root: document.body,
      watch: ['h1', 'h2', 'button']
    });
    dom.attach();
    Object.assign(window, { bee, dom });
  });

Muovi il mouse sulla pagina per vedere margin, padding e content colorati sotto il puntatore. Poi prova a generare una mutazione dalla console:

console
document.body.dataset.test = '1'

Nel pannello compare mutate attr 1. Premi F4 per congelare il box model sull'elemento corrente, F2 per nascondere overlay e contorni, F8 per scaricare il report con la sezione dom.
