Concetti

Il Core è cieco.

BeeLadybugCore non sa se davanti ha un Canvas, il DOM, un processo Python o una pipeline AI. I file in src/adapters/ sono moduli: traducono il loro mondo in pacchetti grezzi. Il Core li timbra, li tiene in memoria e li mostra.

Il Core non importa quei moduli. Riceve solo dati grezzi.

Due strati, un solo ingresso

src/core/BeeLadybugCore.js tiene il clock, i buffer e l'overlay. Quel modulo importa solo UIOverlay e AiAssistant.

L'altro strato è src/adapters/: CanvasAdapter, WebDOMAdapter, CSSAdapter, AntAdapter, SpiderAdapter e python/PythonBridge.js. registerAdapter salva un nome e le funzioni enable / disable. Dentro il Core non c'è un import di questi moduli.

Tutto entra da sendData(type, payload). Un numero o una stringa al posto dell'oggetto diventa { value, message }. Se type non è una stringa non vuota, sendData ritorna null e non emette nulla.

Contratto sendData

WELL_KNOWN_TYPES è la lista dei tipi che l'overlay tratta per primi. Una stringa fuori lista viene comunque salvata in getLatest e inoltrata a subscribe: nel buffer di console ci entra solo se il payload ha level. log, warn, error e debug ci entrano sempre.

Il Core legge solo i campi qui sotto. Chiavi in più restano nel payload e non cambiano HUD né storico: AntAdapter aggiunge node sui warn, SpiderAdapter aggiunge attribution sulla telemetry.

Tipo Campi letti Effetto
fps value oppure fps HUD fps e storico fps. Se il numero non è finito, il pacchetto parte ma HUD e storico restano fermi.
metric name oppure key (default metric), value, unit opzionale HUD sulla serie. Lo storico si aggiorna solo se value è un numero finito. Nel codice: entities, hits, nodes, mutations.
coord label oppure name (default coord), x, y HUD. Se x e y sono entrambi numeri, il valore è x, y. Altrimenti l'HUD mostra il payload intero.
log message, source opzionale, level opzionale Console. Senza level il livello è info.
warn message, source opzionale, level opzionale Console. Senza level il livello è warn.
error message, source opzionale, level opzionale Console. Senza level il livello è error.
state key oppure name (default state), value, unit opzionale HUD. Niente storico.
sys dipende da op, tabella sotto Lo emette il Core. Non entra in HUD né in console. Se lo mandi tu, viene salvato in getLatest('sys') e inoltrato ai subscriber, senza altri effetti.
clear channel oppure type: logs, history, hud Svuota quei buffer. Se il campo manca, svuota tutti e tre. Un valore diverso non svuota nulla. Il pacchetto restituito è sys con op: 'clear'. Non aggiorna getLatest.
telemetry kind oppure name (default telemetry), duration oppure value Solo storico, niente HUD. SpiderAdapter manda kind: 'longtask' e duration. Se source coincide col nome di un modulo registrato, l'overlay fa lampeggiare il suo pulsante (vale anche per warn).
debug message, source opzionale, level opzionale Stesso percorso console di log (livello info se manca). Non è in WELL_KNOWN_TYPES. Nessun modulo in src/ lo emette.

source, se è una stringa non vuota, viene copiato sul pacchetto. Altrimenti il pacchetto porta source: 'adapter'. level parte da payload.level quando c'è; se manca, valgono le regole della tabella e gli altri tipi restano null.

La riga in console mostra payload.message, poi payload.value, poi il nome del tipo.

Comandi sys

I moduli non indovinano il tasto. Ascoltano type: 'sys' e leggono payload.op.

op Campi Quando
boot version Costruzione del Core
visibility visible show / hide
freeze frozen freeze / unfreeze, anche F4
timescale scale setTimeScale, anche F3
adapter name, registered: true, label, hotkey, enabled registerAdapter
adapter name, registered: false unregisterAdapter
adapter name, enabled setAdapterEnabled / toggleAdapter. Qui non c'è registered.
clear op più i campi del payload originale sendData('clear', …)
js
bee.subscribe((packet) => {
  if (packet.type !== 'sys') return;
  const op = packet.payload.op;
  if (op === 'freeze') console.log('frozen', packet.payload.frozen);
  if (op === 'timescale') console.log('scale', packet.payload.scale);
});

CanvasAdapter e WebDOMAdapter fanno questo ascolto e copiano frozen e timeScale sul proprio mondo. Il Core non li mette in pausa da solo.

Tempo reale e tempo fittizio

Ogni pacchetto, oltre a id, type, payload, source e level, riceve tre marche di tempo.

Campo Cos'è
wallTime Date.now(). Millisecondi dell'orologio reale. Il freeze non lo ferma.
simTime Tempo fittizio, in millisecondi. A ogni tick del Core si somma il delta reale, tagliato tra 0 e 100 ms, moltiplicato per timeScale. In overlay lo vedi come mm:ss.s; nel pacchetto resta il numero.
frame frameCount del Core. Parte da 0 e sale di 1 a ogni tick, finché non c'è il freeze. Non è il frame del Canvas.

F3 alterna slowScale (di default 0.25) e 1. Rallenta solo simTime: frame continua a salire a ogni tick. Se il clock era fermo, F3 lo riavvia e poi applica la scala. Se timeScale non è già 0.25, F3 lo porta a 0.25: non ricorda un'altra scala impostata con setTimeScale.

setTimeScale(0) ferma solo simTime. Il frame si ferma soltanto con il freeze.

F4 blocca simTime e frame. L'overlay no: il pannello si ridisegna. I pacchetti nuovi portano un wallTime più alto, mentre simTime e frame restano quelli dell'ultimo tick.

F3 e F4 usano event.code e partono solo con l'overlay visibile. A overlay nascosto risponde solo F2. bee.freeze() e bee.setTimeScale() non guardano la visibilità: sono i metodi. I tasti sono il collegamento quando il pannello è aperto.

▶ Prova in console

Apri una pagina qualsiasi, premi F12 e incolla. Lo snippet carica il modulo bee-ladybug@0.5.4 dalla CDN, lascia correre il clock, poi congela e ristampa wallTime, simTime e frame.

console
import('https://cdn.jsdelivr.net/npm/bee-ladybug@0.5.4/src/index.js')
  .then(async ({ BeeLadybugCore }) => {
    const bee = new BeeLadybugCore();
    window.bee = bee;
    const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

    await wait(300);
    const live = bee.sendData('log', { source: 'console', message: 'live' });
    bee.sendData('fps', { value: 61, source: 'console' });
    bee.sendData('metric', { name: 'nodes', value: 12, source: 'console' });

    bee.freeze();
    await wait(300);
    const frozen = bee.sendData('log', { source: 'console', message: 'freeze' });

    console.log('live  ', live.wallTime, live.simTime, live.frame);
    console.log('freeze', frozen.wallTime, frozen.simTime, frozen.frame);
    bee.unfreeze();
  });

L'overlay parte visibile: F2 lo nasconde. F4, col pannello aperto, fa lo stesso di bee.freeze(). Nella stampa, wallTime cresce; simTime e frame della seconda riga restano quelli della prima.
